# 🚀 Руководство по деплою - ФК Арсенал Дзержинск

## Быстрый старт

```powershell
# Установка переменных окружения (Windows PowerShell)
$env:SSH_USER = "ваш_пользователь"
$env:SSH_HOST = "ваш_хост"
$env:WEB_ROOT = "путь_на_сервере"

# Полный деплой (база + файлы)
.\deploy.ps1

# Только база данных
.\deploy.ps1 -SkipFiles

# Только файлы
.\deploy.ps1 -SkipDatabase
```

## Что делает скрипт

### 1. Экспорт базы данных (2-3 минуты)
- Создаёт полный дамп MySQL с UTF-8 кодировкой
- Заменяет URL при необходимости
- Сохраняет резервные копии в `database/`

### 2. Импорт на сервер (1-2 минуты)
- Загружает дамп на продакшн сервер через SCP
- Импортирует в базу данных через SSH
- Сохраняет все данные: посты, игроки, матчи, статистика

### 3. Загрузка файлов (3-5 минут)
- **Тема Arsenal**: `wp-content/themes/arsenal/`
- **Плагин**: `wp-content/plugins/arsenal-team-manager/`
- **Изображения**: `wp-content/uploads/` (логотипы команд, фото игроков, баннеры)

### 4. Проверка сайта
- HTTP запрос на главную страницу
- Проверка наличия основных элементов
- Отчёт о статусе

## Требования

### Локальная машина
- PowerShell 5.1+
- MySQL 8.4.3 (Laragon)
- SSH клиент (OpenSSH)
- SCP для передачи файлов

### Сервер
- SSH доступ: переменные окружения SSH_USER@SSH_HOST
- MySQL 5.7.42
- PHP 8.3
- Nginx

### Учётные данные

**Локальная БД:**
- База: `arsenal`
- Пользователь: `arsenal_usr`
- Пароль: см. `.env` файл

**Продакшн БД:**
- Установите переменные окружения: SSH_USER, SSH_HOST, REPO_DIR, WEB_ROOT, PROD_PATH

## После деплоя

### 1. Настройка меню (WordPress Admin)

1. Зайдите в админку и перейдите в **Внешний вид → Меню**
2. Создайте новое меню "Главное меню"
3. Добавьте пункты:
   - О клубе
   - Команда
   - Матчи
   - Турнирная таблица
   - Новости
   - Контакты
5. В разделе "Расположение в теме" выберите **Primary Menu**
6. Сохраните меню

### 2. Настройка баннера (Theme Customizer)

1. Перейдите в **Внешний вид → Настроить**
2. Откройте **Arsenal Settings → Banner**
3. Загрузите изображения для слайдов (рекомендуемый размер: 1920x1080px)
4. Заполните заголовки и описания
5. Нажмите **Опубликовать**

### 3. Проверка функциональности

- [ ] Главная страница загружается
- [ ] Меню отображается и работает
- [ ] Баннер показывает слайды
- [ ] Статистика клуба отображается
- [ ] Последние матчи загружаются
- [ ] Турнирная таблица показывает правильные данные
- [ ] Страницы игроков открываются
- [ ] Изображения команд отображаются

```
│   │   └── arsenal/              # Тема (загружается на сервер)

```

## Частые проблемы

### "Access denied for user" при экспорте БД
**Решение:** Проверьте пароль в wp-config.php и в скрипте deploy.ps1

### "Connection refused" при загрузке на сервер
**Решение:** Проверьте SSH подключение:
```powershell
ssh ${SSH_USER}@${SSH_HOST} "echo 'Connected OK'"
```

### Изображения не отображаются
**Решение:** Проверьте права доступа на сервере:
```bash
chmod -R 755 ${WEB_ROOT}/wp-content/uploads/
```

### "Error establishing database connection"
**Решение:** 
1. Проверьте wp-config.php на сервере
2. Проверьте доступ к MySQL:
```bash
mysql -u 1779917_cq85 -p 1779917_cq85 -e "SELECT 'OK'"
```

### Кракозябры вместо кириллицы
**Решение:** Убедитесь что в wp-config.php установлено:
```php
define('DB_CHARSET', 'utf8mb4');
define('DB_COLLATE', 'utf8mb4_unicode_ci');
```

## Исправление проблемы с SSL сертификатом (Let's Encrypt)

Если при выпуске сертификата видите ошибку проверки домена, это часто связано с файлом `/etc/hosts` на сервере.

### Решение (через FastPanel)
1. Зайдите в панель управления FastPanel
2. Перейдите в **Домены** и выберите нужный домен
3. Найдите опцию **Локальное разрешение имен** или **Local DNS override**
4. Отключите/удалите запись для вашего домена
5. Сохраните изменения
6. Попробуйте выпустить сертификат снова

### Если не помогает
Обратитесь в поддержку FastPanel с просьбой удалить запись о домене из `/etc/hosts` на сервере. Поддержка сможет это сделать с правами root.

## Откат изменений

Если что-то пошло не так, восстановите из резервной копии:

```powershell
# На локальной машине
scp database\deploy_backup.sql ${SSH_USER}@${SSH_HOST}:/tmp/restore.sql

# На сервере
ssh ${SSH_USER}@${SSH_HOST}
mysql -u ${DB_USER} -p'${DB_PASS}' ${DB_NAME} < /tmp/restore.sql
```

## Автоматический деплой (CI/CD)

Для автоматизации можно настроить Git hooks или GitHub Actions:

```yaml
# .github/workflows/deploy.yml
name: Deploy to Production
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v2
      - name: Run deploy
        run: .\deploy.ps1
```
